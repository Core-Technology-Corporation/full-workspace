01Resumen

El proyecto

Full Workspace convierte un entorno de trabajo en algo reproducible: una sola instalación desde el Marketplace deja VS Code listo para probar APIs, administrar bases de datos, trabajar en servidores por SSH y levantar un servidor local con recarga automática.

Lo verifiqué instalando el .vsix real en un perfil limpio: VS Code instaló las 9 extensiones del pack más 2 dependencias declaradas por ellas. La publicación está automatizada con un script de PowerShell que versiona, empaqueta y publica en un solo comando.

Problema

Preparar un VS Code nuevo, o el de un compañero de equipo, implica buscar e instalar cada extensión por separado y con criterios distintos.

Objetivo

Reproducir el entorno de trabajo completo con una sola instalación y mantenerlo versionado.

Público

Desarrolladores full stack de habla hispana que trabajan con APIs REST, bases de datos SQL y servidores remotos.

04Arquitectura

Cómo está construido

package.json
  ├─ metadatos de galería   (icon · galleryBanner · categories: Extension Packs)
  └─ extensionPack[9]  ──►  VS Code Marketplace resuelve e instala
        Bookmarks · Path Intellisense · Postman · Spanish Language Pack
        Remote-SSH · Remote-SSH Edit · PowerShell · Database Client · Live Server

scripts/publish.ps1
  npm version <bump>  →  git commit "msg (vX.Y.Z)"  →  npx vsce package
                      →  [-Push] git push  →  [-Publish] npx vsce publish
  • Declarativo: no tiene código de ejecución, así que no agrega costo de arranque propio.
  • El script de publicación se detiene ante el primer fallo ($ErrorActionPreference = 'Stop' y revisión de $LASTEXITCODE).
  • Se puede reutilizar como plantilla cambiando solo la lista de IDs.

06Ingeniería

Decisiones y próximos pasos

Seguridad

  • El pack no ejecuta código propio.
  • Las credenciales (Postman, bases de datos, SSH) las gestiona cada extensión.
  • El script no guarda tokens: usa la sesión de vsce login.

Retos técnicos

  • Elegir extensiones complementarias, sin superposición.
  • Publicar de forma reproducible con un solo comando.

Hoja de ruta

  • Alinear el CHANGELOG con la versión y el contenido actuales.
  • Sacar del repositorio los archivos de análisis ajenos al pack.
  • Agregar capturas a la página del Marketplace.
